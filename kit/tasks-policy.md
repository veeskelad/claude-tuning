# Чек-лист задачи

Любая рабочая задача (кроме вопрос-ответ и правки в один шаг) ведёт чек-лист в файле. Список в
файле переживает сжатие контекста, смену сессии и смену агента; человек смотрит прогресс в нём,
а не в переписке.

## Где лежит

| Задача | Путь |
|---|---|
| В репозитории или worktree | `<корень>/.tasks/<slug>.md` |
| Вне репозитория (папка с проектами, сервер) | `<папка>/.tasks/<slug>.md` |

`<slug>` — тема латиницей через дефис. Один файл на задачу: параллельные сессии не пишут в общий.
`.tasks/` добавить в глобальный gitignore (`git config --global core.excludesFile`), чтобы
чек-листы не попадали в коммиты.

## Формат

```markdown
# <цель одной строкой>

Готово = <проверяемый финиш>. Стоп, если: <что требует человека>.

- [ ] <один проверяемый шаг>
- [x] <сделанный шаг — отмечать сразу по факту>
```

## Приёмка по результату

«Готово» — это проверка, а не ощущение. В строке `Готово =` всегда назван способ проверить финиш: команда и её
ожидаемый вывод, файл, который должен появиться, адрес, число. «Сделать красиво», «настроить X» — не финиш;
«`npm test` зелёный», «`curl -s …/health` отдаёт 200», «в `out/report.md` таблица по 12 строкам» — финиш.

Перед финальным ответом агент выполняет эту проверку и пишет её результат одной-двумя строками. Проверка не прошла
или её нельзя выполнить — пункт остаётся открытым, а в ответе сказано, что не проверено и почему. Различать:

| Статус | Значит |
|---|---|
| сделано и проверено | проверка из `Готово =` прошла в этой сессии |
| сделано, не проверено | файл лёг или команда отработала, но проверку выполнить не удалось (нет доступа, нужен человек) |
| проверено в новой сессии | отдельный запуск без подсказок нашёл и использовал результат (для настроек, хуков, скиллов) |

## Перед новой задачей

До чек-листа проверить, не идёт ли эта работа уже и не делалась ли: несколько открытых сессий легко чинят одно
и то же параллельно и советуют разное.

```bash
~/.claude/bin/related-sessions.py TICKET-123 'ключевое слово' --hours 24
```

Скрипт ищет по транскриптам Claude Code и Codex: где тему обсуждали или делали, когда сессия была активна, как её
вернуть (`claude --resume <id>`). Плюс комментарии задачи в трекере и `.tasks/`. Нашлась живая сессия — написать
ей (`/list-agents`, `@имя`) или продолжить её чек-лист.

## Работа до результата: /goal

Чек-лист создан — агент в том же сообщении предлагает строку для вставки, собранную из шапки файла:

```
/goal <цель>. Готово, когда: <признак из «Готово =»>. Остановиться и спросить, если: <условие из «Стоп, если»>.
```

Человек вставляет её, и сессия работает, пока условие не выполнено, без «продолжить?» после каждого этапа.
Сам агент `/goal` не включает: это встроенная команда Claude Code, вызвать её может только человек. Для задачи
в один-два шага строка не нужна. Нет `/goal` в твоей версии — `claude --version` и обновить.

## Кто читает

- Хук `open-tasks.sh` на старте сессии и после сжатия: показывает незакрытые чек-листы проекта,
  цель и первые открытые пункты; залежавшиеся дольше 7 дней помечает.
- Хук `compact-context.py` после сжатия: возвращает агенту чек-лист, который ведёт именно эта сессия,
  и последние правленые файлы.
- `/morning` и `/endday`: `open-tasks.sh --all` по всем рабочим корням (`CLAUDE_WORK_ROOTS`).
- `session-handoff`: ссылка на чек-лист в записи handoff вместо пересказа пунктов.

Задача закрыта — все пункты `[x]` или оставшиеся закрыты с причиной; файл можно удалить или
перенести в `.tasks/done/`.
