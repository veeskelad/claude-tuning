# Ревью кода: доменные проверки и качество находок

Обычный `/code-review` ищет обычные дефекты — логику, edge cases, утечки, дубли. Здесь то, чего он сам не
ищет: классы багов, которые **проходят CI и падают в проде**, плюс правила, отсекающие выдуманные находки.

Это скилл, а не правило в `~/.claude/rules/`: правило грузится в каждую сессию целиком, а проверки нужны
только на ревью. Приёмку ветки (scope creep, сверка с описанием PR) держит раздел «Дрейф scope».

## Как подключить к ревью

- Ревью в своей сессии — применить разделы ниже к диффу.
- CI-ревью, которое склеивает `CLAUDE.md` репозитория в промпт, увидит правила, только если блок из раздела
  «Готовый блок» лежит в `CLAUDE.md` самого проекта.
- Что именно читает встроенный `/code-review`, не гарантировано: надёжно только явное «примени
  `review-domain-checks`» в запросе или блок в `CLAUDE.md`.

## Доменные проверки

### SQL и сохранность данных
- Интерполяция строк в SQL — даже после `.to_i`/`.to_f`. Только параметризованные запросы.
- TOCTOU: «прочитал → проверил → записал» там, где нужен атомарный `WHERE` + `UPDATE`.
- Обход валидаций модели прямой записью в БД (`update_column`, `QuerySet.update()`, raw-запросы Prisma).
- N+1: отсутствие eager loading для связей, используемых в циклах.

### Гонки и конкурентность
- `find_or_create` без уникального индекса — параллельные вызовы создадут дубли.
- Переходы статусов без атомарного `WHERE old_status = ?` — переход применится дважды или потеряется.
- Небезопасный рендер HTML (`html_safe`, `dangerouslySetInnerHTML`, `v-html`, `|safe`) на пользовательских данных.

### Граница доверия к выводу LLM
- Значения от модели (email, URL, имена) уходят в БД или в рассылку без проверки формата.
- Структурный ответ (массив, объект) принимается без проверки формы до записи.
- URL от модели фетчится без allowlist — SSRF во внутреннюю сеть.
- Вывод модели кладётся в векторную БД без санитизации — сохранённая prompt injection.
- Вывод модели попадает в `eval`, `exec`, SQL, shell или файловый путь.

### Shell-инъекции
- `subprocess` с `shell=True` и f-string в команде; `os.system()` с интерполяцией — только массив аргументов.
- `eval`/`exec` над сгенерированным кодом без песочницы.

### Полнота enum — единственная проверка, которой мало диффа
Появилось новое значение статуса, тарифа, типа:
- Прогрепать и прочитать каждого потребителя: `case`/`if-elsif` (не провалится ли в дефолт), allowlist-массивы
  с соседними значениями.
- Классический промах: значение добавили в дропдаун фронта, бэкенд его не сохраняет.

### Миграции на живой БД
- Откат: есть ли down-миграция, отменяет ли она изменение на самом деле, не сломает ли откат текущий код.
- Потеря данных: удаление непустых колонок, сужение типа (`varchar(255) → varchar(50)`), переименование без
  правки ORM/raw SQL/вью, `NOT NULL` на колонку с существующими NULL.
- Длительность блокировки: `ALTER TABLE` и `CREATE INDEX` без `CONCURRENTLY` на больших таблицах, несколько
  `ALTER` вместо одного, изменение схемы в пик нагрузки.
- Backfill: новая `NOT NULL` без `DEFAULT`, обновление всех строк разом вместо батчей.
- Порядок expand-contract: сначала совместимая схема, потом код, потом снос старого.

### Контракт API и выкатка
- Обратная совместимость ответа и параметров для уже задеплоенных клиентов.
- Побочный эффект (письмо, платёж, вебхук) внутри `if` или после early return — отправится дважды или не отправится.

## Качество находок

- **Гейт цитаты.** Находка не публикуется, пока дословно не процитирована строка `file:line`, из которой она
  следует. «Поля X нет в модели Y» — цитируй тело Y. «Гонка между A и B» — цитируй оба места.
- **Поправка на метапрограммирование.** Символ, порождённый ORM или метаклассом, нельзя объявлять
  отсутствующим по грепу: Django `Meta`, Rails `has_many`/`scope`, SQLAlchemy `relationship`, декораторы
  TypeORM, клиент Prisma. Цитируй метаконструкцию или миграцию.
- **Запрет «вероятно, покрыто».** «Скорее всего обрабатывается» без ссылки на файл — дефект отчёта.
- **UNVERIFIABLE вместо догадки.** Состояние вне репозитория (env облака, RLS, DNS, allowlist OAuth) не
  выдумывать: пометить непроверяемым и назвать конкретную ручную проверку.
- **Обработчик ≠ артефакт.** Пункт не сделан оттого, что рядом появился код, который умеет это обрабатывать.
  Назван конкретный путь — вердикт по `[ -f ]`.
- **Дрейф scope.** Сверить, что сделано ровно заявленное: и лишние правки «раз уж я здесь», и молча
  недоделанные требования.

## Готовый блок для `CLAUDE.md` проекта

Копировать в проекты, где есть БД, внешние API или вызовы LLM и где CI-ревью читает CLAUDE.md.

```markdown
## Code Review Requirements

Кроме обычных дефектов проверять то, что проходит CI и падает в проде:

- **SQL:** интерполяция в запросе (даже после приведения типа), TOCTOU вместо атомарного `WHERE`+`UPDATE`, обход валидаций прямой записью, N+1 в циклах.
- **Гонки:** `find_or_create` без уникального индекса, переход статуса без атомарного условия.
- **Вывод LLM:** значения от модели уходят в БД, рассылку, `eval`, SQL, shell или путь без валидации формы и формата; URL без allowlist (SSRF).
- **Shell:** `shell=True` с интерполяцией, `os.system` с переменной — только массив аргументов.
- **Новый enum:** прочитать (не грепнуть) каждого потребителя — `case`-цепочки и allowlist-массивы; частый промах — фронт умеет, бэкенд не сохраняет.
- **Миграции живой БД:** отсутствие рабочего отката, `ALTER`/`CREATE INDEX` без `CONCURRENTLY`, `NOT NULL` без `DEFAULT` и без backfill, backfill без батчей, сужение типа, удаление непустой колонки.
- **Выкатка:** обратная совместимость API для задеплоенных клиентов; побочный эффект (письмо, платёж, вебхук) под `if` или после early return.

Качество находок:

- Не публиковать находку без дословной цитаты `file:line`, из которой она следует.
- Не объявлять отсутствующим символ, порождённый ORM или метаклассом (`Meta`, `has_many`, `relationship`, декораторы, клиент Prisma) — цитировать метаконструкцию.
- «Вероятно, покрыто» без ссылки на код — не аргумент.
- Состояние вне репозитория (env облака, RLS, DNS) помечать непроверяемым и называть ручную проверку, а не додумывать.
```
