# Session Handoff — завершение работы в проекте

Цель одна: когда сессию закрыли, через день или неделю за минуту понять, что она делала, где остановилась и как её вернуть. Без этого каждое утро начинается с пересказа.

Граница со скиллом `endday`: здесь один проект (его дерево, доки, память); там день целиком по всем проектам. Общее у обоих — **один сквозной файл** `~/.claude/global-handoff.md`: утром `/morning` читает единую картину.

## Живая сессия или закрытая

Сессии Claude Code на одной машине видят друг друга (cross-session messaging, Claude Code 2.1.224+ на macOS, Linux и WSL 2). Поэтому handoff больше не нужен, чтобы передать дела соседу:

- **Сессия открыта** — спросить её напрямую. `/list-agents` (или `/peers`) показывает, кто сейчас работает; в запросе написать `@имя` и вопрос, Claude Code сам доставит сообщение. Записывать ничего не нужно.
- **Сессия закрыта** — сообщение до неё не дойдёт. Тогда работают её запись в `global-handoff.md` (шаг 2), возврат `claude --resume <имя или id>` и разовый вопрос без открытия: `claude -p --resume <id> "что ты сделала и где остановилась?"` (вопрос тратит лимит, как обычный запрос). Найти сессию по теме — скилл `session-search`.

Значит, handoff пишется, когда сессию **закрывают**, и отвечает на один вопрос: что делала эта сессия.

## 0. Имя сессии

Безымянную сессию другие находят с трудом. Если имени нет, дать по задаче: `/rename <задача>` (или `claude -n <задача>` при запуске). По имени её найдёт `/list-agents`, адресует `@имя` и вернёт `claude --resume <имя>`.

## Где что хранится

- **Транскрипты Claude Code** — `~/.claude/projects/<slug>/*.jsonl`, пишутся сами. Поиск по ним — скилл `session-search`.
- **Память проекта** — `~/.claude/projects/<slug>/memory/` и индекс `MEMORY.md`. Ведётся руками, шаг 4.
- **Чек-лист задачи** — `<проект>/.tasks/<slug>.md` (правило — `tasks-policy.md` скилла claude-tuning). Хук `open-tasks.sh` показывает открытые чек-листы на старте сессии.
- `~/.claude/sessions/` — служебное харнесса, не трогать.

## Режимы

- **quick** (по умолчанию) — шаги 1–5 и отчёт.
- **full** (на «full handoff», «deep clean») — то же плюс аудит всего дерева и подтверждение уборки перед удалением.

## 1. Уборка дерева

quick — корень и два уровня; full — всё дерево:

```bash
find . -maxdepth 3 -type f \( -name '*.tmp' -o -name '*.bak' -o -name '*~' -o -name '*.swp' -o -name '.DS_Store' \) \
  -not -path './.git/*' -not -path '*/node_modules/*' -not -path '*/archive/*'
# два файла на одну роль — источник дрейфа
find docs .claude -maxdepth 2 -type f -name '*.md' 2>/dev/null | grep -iE '(v2|v3|new|old|copy|backup|updated)' | grep -v archive
```

На macOS `find` бывает `bfs`: при цепочке длиннее ~15 условий `-o` он молча отдаёт пустой результат. Больше масок — два вызова.

Чисто — одна строка и дальше. Пара файлов на одну роль: канон — тот, на который есть ссылки; уникальное из второго перенести, ссылки обновить. В full до удаления показать список и дождаться ответа. Не трогать `node_modules`, `.git`, сборку и файлы моложе суток без спроса.

## 2. Запись в общий handoff

🔑 Заголовок записи обязан начинаться с `- **Сессия ГГГГ-ММ-ДД` — по этому маркеру `handoff-tier.py` сворачивает старое. Запись без даты остаётся в файле навсегда и раздувает утро.

Под своей секцией `### <проект>`, новая запись **сверху**:

```markdown
### <проект>
- **Сессия <ГГГГ-ММ-ДД> — <что произошло и чем кончилось, одной строкой>**
  - Имя: <имя сессии или id> — вернуть: `claude --resume <имя>`
  - <решения, статус, что осталось>
  - Чек-лист: <путь к .tasks/<slug>.md> — открыто N из M, следующий: <первый `- [ ]`>
  - Ветка: <branch>, изменения: <git diff --stat одной строкой>
```

Чек-лист — источник правды по пунктам: перед записью отметить сделанное, в handoff дать только строку-ссылку. Затем свернуть остывшее (последние 3 дня целиком, до 14 дней — заголовок со ссылкой, старше — в архив по дням):

```bash
~/.claude/bin/handoff-tier.py            # dry-run
~/.claude/bin/handoff-tier.py --apply
```

## 3. Проектные документы

```bash
git diff --name-only "@{yesterday}" HEAD 2>/dev/null || git diff --name-only HEAD~5 HEAD
```

Документ описывает то, что поменялось — обновить; не описывает — не трогать.

## 4. Память проекта

Один факт — один файл в `memory/`, строка-указатель в `MEMORY.md`. Записывать то, что нельзя вывести из репозитория и что понадобится через месяц: как оно устроено на самом деле, ловушки с ценой ошибки, решения с причиной. Не записывать то, что уже в git и CLAUDE.md, и пересказ хода работы.

Проверить, не устарела ли уже записанная память: если сессия изменила описанное — поправить сразу. Память, которая врёт, хуже отсутствующей.

## 5. Worktree и ветки

Скилл `worktree-cleanup`: `scan`, затем `clean` для смерженных. Грязные и неотправленные он показывает и не трогает.

## 6. Коммит

Handoff сам по себе не повод коммитить и пушить — только по просьбе. Формат — конвенция проекта, без AI-подписей.

## 7. Отчёт

Что убрано, что обновлено в доках и памяти, куда записан handoff, что первым в следующий раз — 4–6 строк. Пустой результат тоже называть: «дерево чистое», «память не устарела».
