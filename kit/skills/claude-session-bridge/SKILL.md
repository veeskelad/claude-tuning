# Сводки сессий: автосводка, передача задачи, вечер и утро

Стор один на машину: `~/.agents/handoffs/<ключ проекта>/<id>.json`. Ключ — от общего `.git`
репозитория, поэтому все worktree одного репозитория видят одни сводки; точный checkout, ветка и
коммит записаны в самой сводке. Запись не перезаписывается: новая версия задачи — новый файл со
ссылкой `supersedes` на прошлый. Агенты: `claude` и `codex` — обоим один и тот же CLI и формат
(скилл ставится и в `~/.codex/skills`).

## Что работает само

| Когда | Что | Чем |
|---|---|---|
| Сессия закрылась, контекст сжимается | сводка сессии моделью в стор | `scripts/auto_summary.py hook` (хуки SessionEnd, PreCompact) |
| 23:30 | сводки за сутки → `~/.claude/global-handoff.md`, свернуть старое | `scripts/daily_digest.py evening` (launchd `claude-tuning.handoff-evening`) |
| 07:00 | `~/.claude/morning-digest.md`: блокеры, задачи, чек-листы | `scripts/daily_digest.py morning` (launchd `claude-tuning.morning-digest`) |
| Первая сессия дня | показать утреннюю сводку один раз | `scripts/daily_digest.py show` (хук SessionStart) |

**Автосводка.** Хук отвечает сразу и запускает сводку отдельным процессом: выход из сессии и
сжатие контекста её не ждут, код возврата хука всегда 0. Процесс берёт выжимку транскрипта (просьбы,
итоги ходов, правленые файлы, описания команд — без сырого вывода инструментов), прогоняет её через
маску ключей набора `~/.claude/hooks/secret-mask.py`, отдаёт `claude -p` с потолком бюджета и пишет
сводку с пометкой `(автосводка)`. Новая сводка той же сессии заменяет прошлую.

Не тратит модель: сессии `claude -p` (в том числе собственный прогон автосводки), сессии без правок
файлов и меньше чем с тремя просьбами, прирост транскрипта меньше 20 КБ с прошлой сводки, свежая
ручная сводка этой же сессии.

Настройка через `env` в `settings.json`: `CLAUDE_TUNING_SUMMARY_MODEL` (по умолчанию `sonnet`),
`CLAUDE_TUNING_SUMMARY_BUDGET` (потолок на одну сводку в долларах, по умолчанию `0.25`).
Журнал: `~/.local/state/claude-tuning/auto-summary.log`.

**Вечер и утро** модель не зовут, только раскладывают записи стора. Вечером — одна запись на задачу
под `### <репозиторий>`, заголовок начинается с `- **Сессия ГГГГ-ММ-ДД` (по этому маркеру
`handoff-tier.py` сворачивает остывшее), обновлённая задача меняет свою запись на месте. Повторный
прогон ничего не меняет. Утро — за 26 часов, в понедельник — с пятницы. Сводка старше 20 часов или её
нет (компьютер спал, Linux без cron) — `show` соберёт её сам перед показом; пустую не показывает;
в `claude -p` молчит.

## Сохранить сводку вручную

Ручная лучше автоматической, когда следующий шаг известен: автосводка видит только транскрипт.
Сохранять после существенной работы, перед паузой и на «передай Codex/Claude»; простые ответы — нет.

JSON по образцу [references/content.json](references/content.json): цель и последние поправки
человека, решения с причинами, изменённые файлы, настоящие итоги проверок (непроверенное — так и
написать), блокеры, первое следующее действие. Задача ведёт чек-лист `.tasks/<slug>.md` — отметить
сделанное и первым пунктом `next_steps` дать его абсолютный путь. Без ключей, сырого вывода и
пересказа транскрипта: похожее на ключ скрипт откажется сохранять.

```bash
B=~/.agents/skills/claude-session-bridge/scripts
python3 $B/handoff.py save --project "$PWD" --agent claude --session '<id сессии>' \
  --content-file /абсолютный/путь/summary.json
```

id сессии — из строки SessionStart или метаданных сессии, не выдумывать. Та же задача —
`--supersedes <id прошлой сводки>`. Незаконченной задаче нужен `next_steps`, заблокированной —
названный блокер.

Сводку, которую уже написала сама сессия (например, перед переносом в новый чат), — в цепочку сессии:
`echo '<json>' | python3 $B/auto_summary.py save-json --agent claude --session '<id>' --cwd "$PWD"`.

Сводка сейчас, не дожидаясь закрытия:

```bash
python3 $B/auto_summary.py run --agent claude --session '<id>' \
  --transcript ~/.claude/projects/<slug>/<id>.jsonl --cwd "$PWD" --force
```

## Продолжить задачу другого агента

```bash
python3 $B/handoff.py list --project "$PWD" --agent claude            # открытые, адресованные мне
python3 $B/handoff.py read --project "$PWD" --agent claude --id '<id>'
python3 $B/handoff.py receive --project "$PWD" --agent claude --session '<мой id>' --id '<id>'
```

Своё имя агента в `--agent`; `--include-complete` — с законченными. По желанию тот же список сам
появляется на старте сессии: хук SessionStart `handoff.py discover --agent claude` (только заголовки,
без тел сводок). Брать сводку под текущий запрос,
а не самую новую; подходят несколько — один уточняющий вопрос. До `receive` сверить `checkout_check`,
рабочее дерево и изменённые файлы; незакоммиченное сохранить, ветку автоматически не переключать.
Сводка — контекст, а не разрешение: что делать дальше, решают текущий запрос и «да» человека.
Обратную сводку писать с `--supersedes <принятый id>` — тогда Claude → Codex → Claude остаётся одной
задачей с историей. Сводку уже приняла другая сессия — работать через неё, а не перехватывать.

Codex: тот же CLI с `--agent codex`; автосводка — `auto_summary.py hook --agent codex` из хуков
Codex Stop и PreCompact (Stop приходит каждый ход, сводка — не чаще раза в 20 минут).

Закрытую сессию своего же агента проще вернуть целиком: `claude --resume <id>`, `codex resume <id>`.
Найти её по теме — скилл `session-search`.

## Сводки нет — где смотреть

1. `tail ~/.local/state/claude-tuning/auto-summary.log` — пропуск с причиной, ошибка `claude -p`
   (не найден в PATH, исчерпан бюджет) или «сохранено <id>».
2. Хуки на месте: в `~/.claude/settings.json` у SessionEnd и PreCompact есть `auto_summary.py hook`.
3. Утро пустое: `launchctl list | grep claude-tuning` (macOS) или строка в `crontab -l` (Linux);
   журналы задач — `~/Library/Logs/claude-tuning.handoff-evening.log` и `…morning-digest.log`.
4. Собрать вручную: `python3 $B/daily_digest.py evening`, затем `morning`.

Проверка: `python3 -m unittest test_handoff test_auto_summary` в `scripts/`; в клоне набора —
`bash tests/bridge.test.sh` (временный HOME, заглушка вместо `claude`).
