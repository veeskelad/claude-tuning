# Session Search (Layer 3 Memory)

Поиск по существующим JSONL-транскриптам в `~/.claude/projects/`.

## Входные данные

Пользователь указывает одно или несколько:
- **Ключевые слова**: что искать в сообщениях
- **Проект**: имя проекта или часть пути
- **Дата**: "вчера", "на прошлой неделе", конкретная дата

## Алгоритм

### 1. Определить область поиска

Если указан проект:
```bash
# Найти директорию проекта
ls ~/.claude/projects/ | grep -i "<project_name>"
```

Если не указан — искать в текущем проекте (`~/.claude/projects/-Users-<имя>/` или по cwd).

### 2. Поиск по sessions-index.json (быстрый)

Прочитать `~/.claude/projects/{key}/sessions-index.json`:
- Фильтровать по `created`/`modified` (дата)
- Фильтровать по `firstPrompt` (ключевые слова)
- Получить список подходящих sessionId + fullPath

**Внимание**: index может быть неполным (не все сессии индексированы). Если index не даёт результатов — перейти к шагу 3.

### 3. Grep по JSONL-файлам (полный поиск)

```bash
# Найти user messages с ключевым словом
grep '"type":"user"' ~/.claude/projects/{key}/*.jsonl | grep -i "<keyword>"
```

Для фильтрации по дате:
```bash
# Файлы изменённые в нужный период
find ~/.claude/projects/{key}/ -name "*.jsonl" -newer <date_ref> -not -newer <date_ref_end>
```

### 4. Извлечение деталей

Для найденных сессий — прочитать JSONL и извлечь:
- **User messages**: `grep '"type":"user"'` → `message.content`
- **Изменённые файлы**: `grep '"tool_name":"Write\|Edit"'` → target file paths
- **Tool usage**: `grep '"tool_name"'` → подсчёт по типам
- **Timestamps**: первый и последний entry → длительность сессии

### 5. Вывод

```
## Найденные сессии

### Сессия 1 — <дата> (<длительность>)
**Проект**: <name>
**Первый промпт**: <firstPrompt truncated>
**Ключевые действия**:
- <user message 1>
- <user message 2>
**Файлы**: <changed files list>

### Сессия 2 — ...
```

Если сессий много (>10) — показать top-10 по релевантности, предложить уточнить запрос.

## Ограничения

- JSONL-файлы могут быть большими (до 50 MB). Использовать grep, не читать целиком.
- sessions-index.json может быть неполным. Fallback на grep по файлам.
- Поиск read-only — скилл НИЧЕГО не создаёт и не модифицирует.
