# Изменения

## Не выпущено

- Страж не спрашивает про скрипт удаления, который человек уже просмотрел: хеш файла в `~/.claude/hooks/reviewed-scripts.sha256` (строки как у `shasum -a 256`, путь меняет `CLAUDE_GUARD_REVIEWED`). Сверка по содержимому: правка файла возвращает вопрос. Без списка в режиме bypass вопрос становился отказом, и общие скрипты, которые убирают за собой временный файл (например, передача задачи между агентами), не запускались вовсе.
- Маска ключей вместо отказа: `secret-guard-bash.py` подставляет безопасный вид команды — `cat .env` и `env` показывают только имена, `printenv TOKEN` и `gh auth token` — метку `‹secret ИМЯ sha256:… len:…›`, дампы окружения, процессов (`ps aux`, `docker inspect`, `docker compose config`) и конфигов идут через `secret-mask.py`. Отказ остаётся для приватных ключей и записи значения в документ, историю шелла или файл под git; Write/Edit не вписывает настоящий ключ в файл. `guard-secret-in-output.sh` поднимает тревогу, если значение всё же попало в вывод. Набор ставит `CLAUDE_GUARD_SKIP_SECRETS=1`. Проверка — `tests/leak-replay.py`: 65 классов утечек с фейковыми значениями.
- Чек-лист задачи: агент сразу предлагает готовую строку `/goal` из «Готово» и «стоп» файла — вставил, и сессия работает до результата.
- Меньше подтверждений: хук dippy (ставится отдельно, `pipx install dippy`) сам одобряет команды только на чтение; в SKILL.md — как добавить свои скрипты в `.dippy` проекта и ловушки (симлинк, вызов через переменную, `export` в начале цепочки). Без него режим плана спрашивает «да» на каждый незнакомый скрипт.
- Проверка плана: на `ExitPlanMode` хук-агент сверяет план с кодом до показа и блокирует только дефект с конкретной причиной.
- Страж: свои тестовые контейнеры агент убирает сам (метка `claude.agent.session=<id>`), `docker run -d` без метки — отказ с готовой меткой, `docker container|volume prune` — отказ; `rm -rf` с исключением для временных каталогов проверяет каждый путь, а не всю строку. `CLAUDE_GUARD_SKIP_SECRETS=1` отключает раздел про ключи, если стоит свой страж ключей. Проверка скриптов удаления не ловит сам страж (`… | bash safety-guard.sh` при проверке).
- `worktree-cleanup` не удаляет worktree с игнорируемыми файлами не из кэша сборки (локальные `.env`, state, `tfplan`): `git worktree remove` унёс бы их молча. Оставленные `PUSHED` не входят в «освобождено».
- `memory-consolidate`: индекс памяти обрезается по 200 строкам или 25 КБ, что раньше; упирается обычно в размер.
- `open-tasks.sh`: `~` в `CLAUDE_WORK_ROOTS` (общий `settings.json` на машинах с разным `$HOME`), цель задачи не обрывается посреди буквы.

- Хук `home-clutter.sh`: агент не создаёт новые файлы прямо в домашней папке; в шаблоне CLAUDE.md раздел «Порядок в файлах» (временное в scratchpad, результат в папку темы, одна тема — одно место).
- Шаблон CLAUDE.md: «Первоисточник, а не пересказ» и сверка возраста фактов со старта сессии с часами.
- Ревизия под человека: скилл `self-tune` и `bin/repeat-scan.py`. Повторённые просьбы и поправки становятся правилами в том скилле или CLAUDE.md, где они сработают; действие из трёх разговоров — новым скиллом; длинные скиллы делятся. Правки агент вносит сам, с копией в `~/.claude/tuning-backups/` и записью в `~/.claude/tuning-log.md`. Раз в неделю из `/endday`, сразу — на повторную поправку.
- Детектор повторов ловит круги: последние 2–4 шага повторились три раза (правка, проверка, откат, проверка…), а не только пять одинаковых вызовов подряд.
- Страж спрашивает перед запуском скрипта (`python`, `node`, `bash`… или встроенного кода), который удаляет файлы: 48 218 файлов в сентябре 2026 стёр именно скрипт, а не `rm`.
- Установщик пропускает `__pycache__` в `kit/bin`: раньше падал, если скрипт из набора хоть раз запускали на месте.
- Документация и `--check` установщика проверяют точную команду декабрьского случая `rm -rf tests/ patches/ plan/ ~/`.
- Страж ловит `chmod` с флагами перед `777` (`chmod -R 777 .`), раньше только `chmod 777`.
- Таблица проверки стража в `tests/`: 22 опасные команды (в том числе точная команда декабрьского случая `rm -rf tests/ patches/ plan/ ~/`) и 19 обычных. Запуск: `python3 tests/run-guard.py kit/hooks/safety-guard.sh tests/safety-guard.cases.tsv`.
- Страница: «Это уже случалось с живыми людьми» (пять реальных случаев со ссылками и тем, как набор их предотвратил бы), самопроверка «Что из этого было с тобой?», пример «Подстраивается под тебя», окна-примеры в виде чата приложения с шагами агента простыми словами, обращение на «ты», цифры про пользу для читателя.

## 2.0.0 — 08.10.2026

- Набор `kit/` и установщик `scripts/install-kit.py`: сухой прогон, `--apply`, `--check`, `--uninstall`. Ничего не перезаписывает, перед правкой настроек делает копию.
- Сессии видят друг друга (Claude Code 2.1.224+): открытую спрашивают напрямую (`/list-agents`, `@имя`), handoff теперь про закрытые — имя сессии, `claude --resume`, id в автосохранении.
- `--extra DIR`: свой модуль той же формы поверх набора — личное отдельно от общего.
- Лицензия MIT.
- В набор вошли самые используемые в ежедневной работе скиллы настройки: `session-handoff`, `endday`, `morning`, `memory-consolidate`, `session-search`, `worktree-cleanup`, `systematic-debugging`, `review-triage`.
- Хуки: чек-листы задач на старте сессии и после сжатия контекста, страж опасных команд, страж файлов с ключами, автосейв с ротацией, свежесть клонов, детектор повторов, расхождение `CLAUDE.md` и `AGENTS.md`.
- Страж ловит корневой путь не только первым аргументом: `rm -rf tests/plan/ ~/` (реальный случай декабря 2025) теперь блокируется. Добавлены `drizzle-kit push --force`, `prisma migrate reset`, `git reset --hard`, `git clean -f`, `cat .env`, полный `printenv`. Таблица из 40 команд без ошибок.
- Детектор повторов читает вход хука из stdin: прежняя версия ждала переменных окружения, которых Claude Code не передаёт, и не срабатывала.
- Шаблон CLAUDE.md: правило остановок, чек-лист задачи, «что сохранять при сжатии», запреты — хуками, а не текстом.
