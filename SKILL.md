# Claude Code Tuning

Claude Code из коробки и после настройки — одна и та же модель. Разница в системе вокруг неё. Без неё у каждого одни и те же боли:

| Боль из коробки | Что ставит скилл | Файл в `kit/` |
|---|---|---|
| Каждое утро объяснять заново; после сжатия контекста теряет задачу | чек-лист задачи `.tasks/<slug>.md` + хук, показывающий открытые на старте; возврат задачи после сжатия; `/session-handoff`, `/endday`, `/morning` с общим `global-handoff.md` | `tasks-policy.md`, `hooks/open-tasks.sh`, `hooks/compact-context.py`, `skills/session-handoff`, `skills/endday`, `skills/morning` |
| Лимиты кончаются к обеду | CLAUDE.md-карта на 40–60 строк вместо простыни; сжатие handoff: целиком читаются только последние 3 дня; автокомпакт на 60 % с правилом «что сохранять» | `claude-md.md`, `bin/handoff-tier.py`, `settings.snippet.json` |
| Удалил домашнюю папку, базу, незакоммиченное | хук-страж: блок необратимого, вопрос на рискованное, пропуск остального | `hooks/safety-guard.sh` |
| Вывел ключи из `.env` в чат | хук на чтение файлов с ключами и на `cat .env` / `printenv`; ключи — в `~/.claude/.env`, в чат только имена | `hooks/guard-secret-read.sh`, `safety-guard.sh`, `references/env-template` |
| Правило в CLAUDE.md прочитал, согласился и нарушил | запреты держит хук, а не текст: CLAUDE.md для модели контекст, не принудительная настройка (документация Claude Code, «memory») | `hooks/*` |
| Ходит по кругу, «продолжить?» каждые пять минут | правило остановок в CLAUDE.md; детектор повторов | `claude-md.md`, `hooks/loop-detector.sh` |
| Отставший клон, брошенные ветки и копии репо | worktree от свежего `origin/main`, уборка смерженного, предупреждение об отставании | `skills/worktree-cleanup`, `hooks/repo-freshness.sh` |
| Чинит симптом, спорит с ревью точечно | скиллы `systematic-debugging` (причина до фикса), `review-triage` (замечания классами) | `skills/*` |

Почему именно этот набор: в реальной ежедневной работе (месяц транскриптов, сентябрь–октябрь 2026) чаще всех вызывались `/session-handoff` (108 раз в 76 сессиях), передача задачи между агентами, `worktree-cleanup`, `systematic-debugging`, `review-triage`, `memory-consolidate`. Рабочие доменные скиллы у каждого свои и в набор не входят. Пересчитать у себя — шаг 1.

Подтверждение перед любым удалением и перед правкой чужого. Никаких значений ключей в выводе.

## Режим

- **Новая машина или новый человек** — шаги 1 → 3 → 2 → 4–8 → 9. Основная работа делает `install-kit.py`, остальное — CLAUDE.md и проверка.
- **Ревизия существующей настройки** — шаг 1 (аудит), затем только то, что аудит показал. Своё не перетирать: установщик ставит недостающее и сообщает «своя версия», если файл есть и отличается.

## 1. Аудит

Запустить субагента (Explore) на `~/.claude/` и `~/.agents/`:
- `~/.claude/CLAUDE.md` — строк, жёсткие правила («ОБЯЗАТЕЛЬНО», «НИКОГДА»), правила, спорящие с описаниями инструментов;
- `~/.claude/settings.json` — хуки, разрешения, плагины, **секреты в `env`**;
- скиллы: канон `~/.agents/skills/`, ссылки `~/.claude/skills`, `~/.codex/skills`; битые ссылки, копии вместо ссылок;
- `~/.claude/projects/` — число, дубли, сироты.

Реальная нагрузка на контекст, а не только размер CLAUDE.md:

```bash
cat ~/.claude/CLAUDE.md ~/.claude/rules/*.md 2>/dev/null | wc -c        # грузится всегда, токенов ≈ символы / 4
grep -rl SessionStart ~/.claude/plugins/cache/*/*/*/hooks/*.json 2>/dev/null   # инъекции плагинов на старте
wc -c ~/.claude/global-handoff.md 2>/dev/null                            # его /morning читает целиком
```

Ориентир — до ~20 тыс. токенов на старт. ⚠️ `find` на macOS бывает `bfs`: при цепочке длиннее ~15 условий `-o` молча возвращает пусто — разбивать на части.

Какие скиллы реально нужны этому человеку — посчитать вызовы по транскриптам (`tool_use` с именем `Skill` и `<command-name>` в сообщениях) в `~/.claude/projects/*/*.jsonl`. Часто вызываемое ставится в первую очередь, ни разу не вызванное за месяц — кандидат в `~/.agents/skills-disabled/`.

Отчёт: что есть, чего не хватает, что лишнее.

## 2. CLAUDE.md → карта

Больше ~80 строк или жёсткие правила — переписать по `kit/claude-md.md`. Не копировать шаблон поверх чужого файла: перенести из старого только то, что модель без этого сделает неправильно и ошибку не поймает ни линтер, ни CI.

Правила Claude 5 («The New Rules of Context Engineering», «Getting the most out of Opus 5.5», 22.09.2026):
- конфликт инструкций дороже пробела — модель тратит рассуждения на примирение;
- убрать «think hard / step by step / покажи рассуждения» — глубину задаёт effort;
- правило остановок обязательно: иначе модель сама заканчивает ход сводкой и «продолжить?»;
- запреты на опасные команды текстом не писать — их держат хуки (шаг 4);
- раздел «При сжатии контекста сохранять» — единственный способ повлиять на автокомпакт (шаг 7).

Типовые кандидаты на удаление: «N файлов → субагент» (спорит с правилом harness о вызове Agent), «после правки перечитай файл» (спорит с описанием Read), «спроси перед началом» (спорит с «make routine judgment calls»).

Работаете и в Claude, и в Codex — общие правила в один файл (например, `~/.agents/POLICY.md`), на него ссылаются `CLAUDE.md` и `AGENTS.md`, а не копируют. `AGENTS.md` рядом с `CLAUDE.md` всегда расходится: лучше симлинк и агент-нейтральный текст; хук `agents-md-drift.sh` предупреждает о правке одного из пары.

## 3. Установка набора

Скрипт лежит в папке этого скилла (`~/.claude/skills/claude-tuning/` или `~/.agents/skills/claude-tuning/` — где он установлен):

```bash
K=~/.claude/skills/claude-tuning; [ -d "$K" ] || K=~/.agents/skills/claude-tuning
python3 "$K/scripts/install-kit.py"                        # сухой прогон: что поставит
python3 "$K/scripts/install-kit.py" --apply                # поставить
python3 "$K/scripts/install-kit.py" --check                # проверить
python3 "$K/scripts/install-kit.py" --uninstall [--apply]  # снять поставленное
python3 "$K/scripts/install-kit.py" --extra DIR [--apply]  # плюс свой модуль поверх kit (повторяемый)
```

Личное человека (свои серверы, пути, хуки) — не правкой `kit/`, а своим модулем той же формы (`skills/`, `hooks/`, `bin/`, `settings.snippet.json`) через `--extra`: набор остаётся общим и обновляется без конфликтов.

Сначала показать человеку сухой прогон и получить «да» на `--apply`: установщик меняет `~/.claude/settings.json` (с бэкапом).

Что делает `--apply`:
- скиллы из `kit/skills/` → `~/.agents/skills/` (канон), ссылки из `~/.claude/skills` и `~/.codex/skills`;
- хуки из `kit/hooks/` → `~/.claude/hooks/`, `handoff-tier.py` → `~/.claude/bin/`;
- вливает в `settings.json` хуки, `env`, `worktree.baseRef: fresh`, пустую `attribution` — только недостающее; перед правкой — бэкап `settings.json.bak-ГГГГММДД` (если моложе 7 дней бэкапа нет);
- создаёт `CLAUDE.md` по шаблону, только если его нет; `global-handoff.md`-каркас; `.tasks/` в глобальный gitignore.

Ничего не перезаписывает: файл с тем же именем и другим содержимым остаётся, в отчёте — «своя версия» и команда `diff` для сравнения. Повторный `--apply` ничего не меняет.

Ставится вручную (чужие репозитории, их установщиком — `kit` их не копирует): `find-skills` и `skill-creator`, команды печатает установщик. Флаги проверить в `npx skills --help`.

`--uninstall` снимает только файлы, совпадающие с `kit/`, и только хуки kit из настроек; свои правки, чужие хуки, `env`, `CLAUDE.md`, handoff и чек-листы остаются.

Проверено 08.10.2026 в пустом HOME с чужим хуком в настройках: сухой прогон, `--apply`, `--check` («всё на месте», страж блокирует `rm -rf tests/plan/ ~/`), повторный `--apply` без изменений, `--uninstall --apply` — чужой хук и своя правка на месте.

## 4. Хуки безопасности

`safety-guard.sh` (PreToolUse, Bash) — три уровня:
- **deny**: `rm -rf` по корню, домашней папке или `$HOME` (в том числе не первым аргументом: `rm -rf tests/plan/ ~/` в декабре 2025 снёс у пользователя домашнюю папку вместе с Keychain), `drop database|table|schema`, `terraform destroy`, `drizzle-kit push --force`, `prisma migrate reset`, `git reset --hard origin/…`, `kubectl delete`, `docker system prune`, `npm publish`, `chmod 777`; вывод `.env` и ключей командой; полный `printenv`/`env`;
- **ask**: `rm -rf` по абсолютному пути вне временных каталогов, `git reset --hard`, `git clean -f`, `git push --force`, `git branch -D`, остановка сервисов, `reboot`;
- остальное — пропуск. Тело heredoc при записи файла не проверяется: это данные, а не команды. Чтение текста (`grep "rm -rf /" docs/`) не блокируется.

`guard-secret-read.sh` (PreToolUse, Read): `.env*` (кроме `.example`), `*.pem`, `*.key`, ssh-ключи, `credentials*.json`, `.netrc`. Точечное разрешение — `CLAUDE_SECRET_READ_ALLOW`.

Проверка — таблица «команда → ожидаемое решение» на каждый паттерн, плюс ложные срабатывания (`rm -rf node_modules`, `rm -rf ./build /tmp/x`, `env FOO=1 node app.js` должны проходить). Новый паттерн — новая строка в таблице до правки стража.

Режим bypass: хуки PreToolUse работают и в нём; `ask` там превращается в отказ без вопроса — это нормально.

## 5. Передача работы между сессиями

Слои — от частого к редкому:

1. **Чек-лист задачи** `.tasks/<slug>.md` (`kit/tasks-policy.md`) — правда о пунктах. Хук `open-tasks.sh` на старте и после сжатия показывает открытые; `compact-context.py` после сжатия возвращает именно ту задачу, которую вела сессия, и правленые файлы.
2. **`/session-handoff`** в конце работы в проекте: уборка дерева, запись `- **Сессия ГГГГ-ММ-ДД — …**` в `~/.claude/global-handoff.md`, обновление доков и памяти, уборка worktree.
3. **`/endday`** — итог дня по всем проектам; **`/morning`** — утром читает тот же файл и открытые чек-листы.
4. **`session-autosave.sh`** (SessionEnd, PreCompact) — машинная запись ветки и незакоммиченного в `~/.claude/handoff.md`, с ротацией.

Рост handoff — главная утечка токенов по утрам. Реальные числа из настройки, на которой собирался набор: машинный handoff дорос до 1987 записей и 863 КБ; `global-handoff.md` за неделю — до 74 КБ, около 18 700 токенов каждое утро. Лечение — `handoff-tier.py --apply` после записи: до 3 дней целиком, до 14 — заголовок со ссылкой `[детали]`, старше — в `~/.claude/handoff-workspace/ГГГГ-ММ/ГГГГ-ММ-ДД.md`. Ничего не удаляется. Условие: **каждый** пишущий в файл начинает запись с маркера `- **Сессия ГГГГ-ММ-ДД`; запись без даты остаётся навсегда. Проверка: второй `--apply` подряд обязан дать «0% меньше».

Два агента (Claude и Codex) на одной задаче — нужен отдельный модуль передачи задачи между ними; в базовый набор он не входит.

## 6. Память

- `~/.claude/projects/<slug>/memory/MEMORY.md` — индекс до 200 строк, один факт — один файл. Создать, если нет, плюс `user_profile.md` (роль, стек, предпочтения — спросить).
- `/memory-consolidate` — аудит: потолок индекса, битые ссылки, сироты, раздутые записи. Предлагать, когда `MEMORY.md` больше 150 строк.
- `/session-search` — поиск по транскриптам: «что я делал вчера», «когда трогали X».
- `lessons-learned.md` — только грепом, файл растёт до сотен КБ.

## 7. Настройки и автокомпакт

`kit/settings.snippet.json`: `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=60` (дефолт срабатывает поздно и режет детали; ниже 45 — слишком часто), `ENABLE_TOOL_SEARCH=auto:5`, `worktree.baseRef: fresh` (новые worktree от `origin/main`, а не от отставшего локального main), пустая `attribution` (без подписей в коммитах и PR). Язык ответов, Agent Teams, модель и effort — спросить у человека.

Секреты в `env` настроек не держать: `settings.json` читает любой процесс пользователя и он попадает в бэкапы. Их место — `~/.claude/.env` (шаблон `references/env-template`), который подгружает профиль шелла; до удаления ключа из настроек проверить, что профиль реально его сорсит.

Автокомпакт: компактор видит CLAUDE.md, поэтому раздел «При сжатии контекста сохранять» в нём — единственный рычаг. PreCompact-хук инструкции задать не может (`additionalContext` у PreCompact нет — проверено по схеме 2.1.220), умеет только блокировать: ненулевой код возврата или зависание без `timeout` = «автокомпакт не срабатывает». Каждый PreCompact-хук — с `timeout` и явным `exit 0`; вернуть контекст после сжатия может только SessionStart с matcher `compact` (`compact-context.py`).

## 8. Скиллы — один склад

Канон — `~/.agents/skills/<name>/SKILL.md`, во все точки доступа — симлинки, копий не бывает. Отключённый скилл — в `~/.agents/skills-disabled/` с удалением ссылок, а не битая ссылка. Проверка:

```bash
find ~/.codex/skills ~/.claude/skills -maxdepth 1 -mindepth 1 -type d   # копии вместо ссылок
find -L ~/.codex/skills ~/.claude/skills -maxdepth 1 -type l            # битые ссылки
```

Скиллы из чужих репозиториев (`~/.agents/.skill-lock.json`) описывают чужой проект: пути, формат коммитов, AI-подписи. Прочитать до использования; переписанный — пометить в теле «форк, апстрим такой-то, дата», иначе обновление молча затрёт правку.

## 9. Проверка и отчёт

```bash
python3 "$K/scripts/install-kit.py" --check
```

Плюс вручную: новая сессия показывает открытые чек-листы; `printf '{"tool_input":{"command":"rm -rf ~/"}}' | bash ~/.claude/hooks/safety-guard.sh` даёт `deny`; `/morning` читает handoff.

Отчёт человеку: что поставлено, что оставлено как «своя версия», нагрузка на контекст до и после (символы / 4), что поставить вручную. Очистку (`~/.claude/projects/` — дубли и сироты, старые `.bak-*` старше 7 дней) — только списком и с подтверждением.

## Обновление набора

Правка в `kit/` — сначала проверка в пустом каталоге (`--home <пустая папка> --apply`, затем `--check` и повторный `--apply` без изменений), потом установка себе. В `kit/` не должно быть личных путей, имён серверов и проектов: набор ставится другим людям. Свою доработку хука держите в `~/.claude/hooks/` — установщик её не тронет и покажет как «своя версия».
