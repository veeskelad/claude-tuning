# Редакция claude-tuning

Сайт и описание набора отстают от кода, когда за ними никто не следит: 18.11.2026 на сайте нашлись старый промпт, версия 2.0.0 в подвале и числа, которые за 12 дней разошлись с тестами. Редакция проверяет это сама и приносит PR.

Людям, которые ставят набор, эти файлы не нужны и `install-kit.py` их не копирует.

## Из чего состоит

| Файл | Что делает |
|---|---|
| `scripts/editorial-check.py` | Без модели. Считает из первоисточника всё, что на сайте записано числом, и сверяет со страницей: опасные и обычные команды (прогон `kit/hooks/safety-guard.sh` по `tests/safety-guard.cases.tsv`), хуки (`kit/settings.snippet.json`), версию, промпт установки, длину шпаргалки. Плюс справку по хукам, список скиллов в `SKILL.md` и CHANGELOG против `VERSION` и тега |
| `scripts/editorial/AGENT.md` | Задание агенту: что сверять, что считать находкой, как писать правку и формат ответа |
| `scripts/editorial/run.py` | Обёртка для расписания: копия от `origin/main`, сбор, агент, проверки после правки, коммит, push ветки `editorial/<дата>`, PR |

## Как считается «хуков»

Один скрипт — один хук, даже если он висит на двух событиях. Обёртки `bypass-ask-to-deny.sh` и `unless-bypass.sh` не считаются, считается то, что они запускают. Хук-агент считается один на свой matcher. Необязательный dippy не считается. Правило записано в `hook_handlers()`; меняется правило — меняется и текст сайта.

## Запуск

```bash
python3 scripts/editorial-check.py
```

```bash
python3 scripts/editorial/run.py --dry-run
```

```bash
python3 scripts/editorial/run.py
```

Первая команда работает за секунды и годится перед любым PR. Вторая собирает всё и спрашивает агента в режиме чтения, ничего не меняя. Третья в боевом режиме открывает PR. С `--local` боевой режим делает правку и коммит во временной копии, но ничего не отправляет: так удобно проверить агента после правки `AGENT.md`.

Первый прогон без сохранённого состояния читает журнал Claude Code с установленной версии (`claude --version`). Читать с более ранней версии можно с `--since-cc 2.1.300`.

Модель зовётся, только если есть что разбирать: расхождения, новые записи журнала Claude Code или коммиты набора после прошлого прогона. Потолок трат одного прогона задаёт `--budget` (по умолчанию $1,5), модель — `--model` (по умолчанию sonnet). Пока открыт PR редакции, новый не открывается.

Состояние (последняя прочитанная версия Claude Code, последний коммит) и журналы лежат в `${XDG_STATE_HOME:-~/.local/state}/claude-tuning-editorial/`. Уведомление о PR или сбое уходит командой из `EDITORIAL_NOTIFY`, если она задана.

## Что редакция не делает

Не мержит, не ставит тег, не запускает `release.sh` и ничего не публикует. Сайт отдаётся прямо из `main`, поэтому всё, что попадает на страницу, проходит через PR и решение владельца.

Агент запускается с `--restricted --tools Read,Grep,Glob[,Edit,Write] --strict-mcp-config`. Он не читает настройки человека, Bash и MCP у него нет, файлы он пишет только внутри временной копии. Одного `--allowedTools` мало: этот флаг добавляет разрешения к настройкам человека, и при `defaultMode: bypassPermissions` агент получил бы всё. Проверить границу на деле можно командой `run.py --probe`: агент пробует запустить Bash и записать файл вне копии, а обёртка смотрит, что появилось на диске. После обновления Claude Code пробу стоит повторить.

Агент правит только тексты: `docs/index.html`, `SKILL.md`, `README.md`, `UPDATE.md`, `CHANGELOG.md` и `.md` внутри `kit/`. Правку кода набора он описывает предложением, потому что тесты на неё обёртка не гоняет. Git, push и PR выполняет обёртка, после того как правка прошла `build-page.py`, `editorial-check.py` и `git diff --check`.

Если фразу на сайте переписали и проверка больше не находит своё место, `editorial-check.py` пишет находку `anchor` и выходит с кодом 1: число на странице не должно остаться без присмотра молча.

## Расписание

`run.py --plist` печатает задание launchd на понедельник в 10:00. Запускать редакцию нужно из отдельного клона на `main`: клон, который служит установленным набором, для этого не годится. Перед каждым прогоном обёртка сама подтягивает этот клон до `origin/main`, если в нём нет своих правок.
